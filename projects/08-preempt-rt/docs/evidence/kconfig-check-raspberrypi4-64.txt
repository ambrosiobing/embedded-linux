This is the check the whole kernel side of Project 8 exists to pass.
CONFIG_PREEMPT_RT depends on EXPERT && ARCH_SUPPORTS_RT, and arch/arm64
gained that select in 6.12 while meta-raspberrypi scarthgap still defaults
to 6.6. On 6.6 the option is silently dropped and the board boots a kernel
that is not preemptible while the results table claims otherwise.

Three facts had to line up, and each was checked separately:

  1. the version pin took            head -4 of the kernel's own Makefile
  2. every fragment line is a symbol  ./go ksym -f rt
  3. every line reached the .config   ./go kconfig -f rt, below

Step 1, from the unpacked source at
~/bench/build/tmp/work-shared/raspberrypi4-64/kernel-source/Makefile:

NOTE ADDED 16 September 2026, after the board was confirmed
-----------------------------------------------------------

Everything above was captured for MACHINE raspberrypi4-64 and is left
exactly as captured, because evidence that is edited afterwards is not
evidence. The board the MCC 118 is actually stacked on turned out to be a
Raspberry Pi 3 Model B v1.2, so the machine is now raspberrypi3-64 and
this check has to be run again against that tree.

What the rerun is expected to change and what it is not:

  changes    the paths, which carry the machine name, and the defconfig
             the fragments are merged on top of
  unchanged  the kernel version, because PREFERRED_VERSION_linux-
             raspberrypi is set in kas/bench-rt.yml and is not a machine
             property
  unchanged  ARCH_SUPPORTS_RT, which arch/arm64/Kconfig selects for the
             architecture and not for the SoC

So the expected outcome is the same 31 lines, from a different directory.
If it is not, that is the finding, and it goes in the journal before
anything else is built.

The rerun happened the same day and is in kconfig-check.txt, alongside this
file. It went as predicted: same 31 lines, same kernel, different directory.
This file was renamed to carry its machine, and kconfig-check.txt is now the
live evidence for the board the project actually runs on.

One thing the rerun found that this file could not. Both checks were reading
their input through a lexical sort, so with two machines present on the
build host ./go ksym read this machine's tree while ./go kconfig read the
other one, and printed the right answer anyway because both were 6.12.93 for
arm64. See journal entry 35. The rerun's output names the tree it did not
read, which is why that line appears in kconfig-check.txt and not here.
