SO THE ORDER OF THE NEXT TWO STEPS IS DETERMINED, AND IT IS NOT OBVIOUS

  bench-pki.sh clock-rule requires CA notBefore < image build time. A CA
  created now gets a notBefore later than 10:45:28 UTC today, so the rule
  would be broken the moment the CA exists, and the script would say so:

    CLOCK RULE BROKEN: the CA is newer than the image.

  The board has no real-time clock and no uplink, so at boot its clock is
  moved forward to roughly the image build time and no further. A CA newer
  than the image means every certificate on the bench reads as not yet
  valid, and every client fails with an error naming the certificate rather
  than the clock. That is the failure this project documented in advance,
  in docs/DESIGN.md under the clock, before any of it was built.

  So: create the CA FIRST, then rebuild the image. In that order the
  rebuild stamps /etc/timestamp later than the CA and the rule holds. The
  rebuild costs 1 min 41 s at the current sstate match, so the whole cost
  of doing it in the right order is under two minutes. The wrong order
  costs a board that comes up with nothing valid.

  Neither step is taken here. bench-pki.sh init mints a private key, the
  script's own header says that key never leaves the laptop, and which
  machine owns it is Joseph's decision rather than this file's.
