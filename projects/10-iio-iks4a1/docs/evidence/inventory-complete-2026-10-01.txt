CRITERION 1 IS MET. Every address answers, the four parts the overlay
binds all report the expected name, and the SHT40AD1B appears through
hwmon. Four addresses now read UU where this morning one did.

CRITERION 2 WAS ALREADY MET AND THIS IS THE SAME PROGRAM SAYING SOMETHING
DIFFERENT, which is the point of it. On Thursday morning the same command
reported four rows of no-driver-in-image. There are none now. The
inventory did not change because the program changed; it changed because
the image did, and the program said so both times without being edited.

THE TWO unsupported ROWS ARE CORRECT AND DELIBERATE. Neither the STTS22H
nor the LIS2DUXS12 has a mainline driver. An inventory that quietly
dropped them, or that called them failures, would be worse than one that
names them and says why. A part with no driver is a finding.

0x6a IS STILL not-bound AND THAT IS THE DISTINCTION CRITERION 7 EXISTS TO
MAKE. The driver is loaded. The part is on the bus. The overlay declares
no node for it, so nothing matched. That is a different fault from 0x1e
this morning, where a node existed and the driver did not, and from 0x38,
where no driver exists anywhere. Three causes, three verdicts, all three
visible in one table.

WHAT IS STILL OPEN AT 0x6a. Whether st_lsm6dsx carries a compatible for
the LSM6DSO16IS can now be answered from the source unpacked on this card
rather than guessed. If it does, a node in the overlay would bind a fifth
part and a third IIO device pair.

THE TRIGGERS ARE LISTED TOO. t100 is the hrtimer trigger criterion 3 was
measured on; iio-rate-t is the one iio-rate creates for its own trigger
runs. Both are visible to the IIO core, which is what iio-trigger checks
and what distinguishes a real trigger from a configfs directory that
merely looks like one.
