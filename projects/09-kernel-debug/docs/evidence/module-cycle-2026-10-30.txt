concerns the module is the O in "Tainted: G B W O", which says an
out-of-tree module is loaded and is a statement about provenance rather
than behaviour.

60 in twenty seconds with no module activity, all 60 from dwc or hcd,

what the ten cycles contained, so the module contributed none of them.
Three matches per report (BUG:, Tainted:, Call trace:) makes it about one
report per second at roughly thirty lines each.

A CONSEQUENCE WORTH MORE THAN THIS CRITERION. At thirty lines a second the
kernel ring buffer holds well under a minute of history, and the module's
own init message was evicted before it could be read:

root@raspberrypi3-64:/# cd / && dmesg | grep -i buggy
root@raspberrypi3-64:/#

Empty, several minutes after the cycles. buggy's init prints a line on
every load, so twenty-odd lines existed and were flooded out. The messages
were not absent, they were overwritten. That bears directly on criterion
6: a KASAN report is a long dmesg dump and can be evicted before it is
read, which argues for log_buf_len on the kernel command line, in the
recipe rather than hand-edited onto the card.
